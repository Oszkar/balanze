# v0.5.2 Legibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the mdBook docs site from a two-page skeleton with published placeholders into the canonical user-facing documentation, and stop the README from being a second manual.

**Architecture:** The book's source directory moves to `docs/src/`, so "published" becomes a property of location rather than of file extension. Three new chapters absorb the long-form content the README currently carries, the user guide gets real screenshots from the existing states gallery, and a new path-filtered CI workflow link-checks the built book *and* the README together so the two cannot drift apart silently.

**Tech Stack:** mdBook 0.5.4, GitHub Pages via the native Actions flow, lychee 0.24.2 for link checking, Playwright (already configured) for screenshot capture, Bun for scripts.

**Spec:** `docs/superpowers/specs/2026-07-29-v0.5.2-legibility-design.md`. Read it before starting. Section references below (for example "spec 3.7") point into it.

## Global Constraints

- **No em dashes, no en dashes, no Unicode ellipsis** anywhere - prose, code, commit messages, PR text. Use `-` and `...`. This is AGENTS.md section 3.5 and it is enforced by a new CI scan in Task 3.
- **No runtime application behavior changes.** No crate logic, no Tauri command or event, no Svelte component, no settings schema. Non-runtime code (a Playwright spec, a package script, workflow YAML) is in scope.
- **Conventional Commits**, enforced by a blocking `commit-msg` hook: `<type>(scope)?: subject`. PR titles must match too (CI-validated).
- **Never use `--no-verify`** or `--no-gpg-sign`. If a hook fails, fix the cause.
- **Branch naming:** `docs/...` for every branch in this plan. One PR per branch.
- **Markdown has no column cap.** Never reflow a paragraph to hit a width.
- **Pinned tool versions** are fetched as prebuilt binaries verified against a SHA-256, never `cargo install`. This keeps CI fast and leaves the vetted Cargo dependency graph untouched.

### Task 3: The pre-merge docs gate

**Files:**
- Create: `.github/workflows/docs.yml`

**Interfaces:**
- Consumes: `book.toml` with `create-missing = false` (Task 1), `docs/src/` (Task 1).
- Produces: the `docs` check that every later PR in this plan runs against. Task 5 extends its page list.

**Why a separate workflow, not a job in `ci.yml`:** GitHub applies `paths` filters to the workflow's `on:` event, never to an individual job. `ci.yml` triggers on every PR with no filter and owns the required `linux` and `cargo-deny` checks, so adding `paths` there to scope a docs job would suppress the whole workflow on code PRs and leave two required checks pending forever, blocking every merge.

- [ ] **Step 1: Write the workflow**

Create `.github/workflows/docs.yml`:

```yaml
name: docs

# Pre-merge gate for the docs site. pages.yml cannot do this job: it runs only
# on push to main (post-merge), and the artifact it builds contains no README,
# so it can never check README-to-site navigation - which is exactly what the
# v0.5.2 deduplication creates.
#
# This is a separate workflow rather than a job in ci.yml because GitHub applies
# `paths` to the workflow event, not to a job. ci.yml runs unfiltered on every PR
# and owns the required `linux` and `cargo-deny` checks; adding a path filter
# there would leave those pending on code-only PRs and block merges.
#
# Not currently a required status check. Promoting it means dropping this path
# filter (a filtered workflow reports nothing on non-matching PRs, so a required
# check would hang) or adding a companion always-reporting job.

on:
  pull_request:
    branches: [main]
    paths:
      - "README.md"
      - "docs/src/**"
      # Top-level docs the README links to. Renaming one without touching
      # README.md or docs/src/** would otherwise skip the gate and land a dead
      # link. Deliberately not docs/**, which would fire on every spec and plan edit.
      - "docs/*.md"
      - "theme/**"
      - "book.toml"
      - ".github/workflows/docs.yml"
  workflow_dispatch:

permissions:
  contents: read

jobs:
  docs:
    name: docs
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7

      # Prebuilt binaries verified by SHA-256, matching pages.yml's approach:
      # fast, and it keeps the workspace's vetted Cargo graph untouched.
      - name: Install mdBook
        env:
          MDBOOK_VERSION: v0.5.4
          MDBOOK_SHA256: 3f28de05dafca9d0f2eab99c662116b0e37b89b1d96a08f8f430b9eeae958cd7
        run: |
          curl -sSL --fail -o mdbook.tar.gz "https://github.com/rust-lang/mdBook/releases/download/${MDBOOK_VERSION}/mdbook-${MDBOOK_VERSION}-x86_64-unknown-linux-gnu.tar.gz"
          echo "${MDBOOK_SHA256}  mdbook.tar.gz" | sha256sum -c -
          tar -xzf mdbook.tar.gz -C /usr/local/bin
          rm mdbook.tar.gz

      # NOTE: unlike mdBook's, this archive extracts into a subdirectory, so it
      # needs --strip-components and an explicit member path.
      - name: Install lychee
        env:
          LYCHEE_VERSION: lychee-v0.24.2
          LYCHEE_SHA256: 1f4e0ef7f6554a6ed33dd7ac144fb2e1bbed98598e7af973042fc5cd43951c9a
        run: |
          curl -sSL --fail -o lychee.tar.gz "https://github.com/lycheeverse/lychee/releases/download/${LYCHEE_VERSION}/lychee-x86_64-unknown-linux-gnu.tar.gz"
          echo "${LYCHEE_SHA256}  lychee.tar.gz" | sha256sum -c -
          tar -xzf lychee.tar.gz --strip-components=1 -C /usr/local/bin lychee-x86_64-unknown-linux-gnu/lychee
          rm lychee.tar.gz

      - name: Build book
        run: mdbook build

      # create-missing = false turns a SUMMARY entry with no file into a build
      # failure, but it says nothing about a chapter that exists and is empty.
      # Assert the pages are there and carry their content heading. mdBook also
      # emits an <h1 class="menu-title"> in the nav bar on every page, so match
      # the content heading's closing markup specifically.
      - name: Assert expected pages
        run: |
          set -euo pipefail
          check() {
            local file="$1" heading="$2"
            if [ ! -f "book/$file" ]; then
              echo "::error::missing book/$file"
              return 1
            fi
            if ! grep -q ">${heading}</a></h1>" "book/$file"; then
              echo "::error::book/$file has no content <h1> reading '${heading}'"
              return 1
            fi
            echo "ok: book/$file (<h1> ${heading})"
          }
          check index.html "Balanze"
          check GUIDE.html "Balanze user guide"

      # AGENTS.md section 3.5 bans em dashes, en dashes, and the Unicode ellipsis.
      # Matched as UTF-8 byte sequences rather than with grep -P, whose Unicode
      # escapes depend on the runner's locale.
      #
      # Full-tree, not diff-scoped: a CI checkout has no staging area, so a
      # `git diff --cached` scan would inspect nothing, and the prohibition is
      # repository-wide anyway.
      - name: Punctuation scan
        run: |
          set -uo pipefail
          # GitHub runs `run:` steps under `bash -e {0}`, and `set -uo pipefail`
          # does not cancel that -e. Since grep's exit 1 (no match) is this step's
          # SUCCESS case, -e would kill the script on a clean scan, before any
          # check happened. Turn it off explicitly and manage grep's status below.
          set +e
          # grep exits 0 (found), 1 (clean), or 2+ (error - unreadable path, bad
          # pattern). A bare `if grep ...` reads 2 as "clean" and the step goes
          # green having checked nothing, so capture the status and treat anything
          # other than 1 as failure. Two of the defects this milestone fixes existed
          # precisely because a green result was trusted.
          #
          # -I skips binary files. docs/src/assets and theme hold PNGs, and a chance
          # byte match inside one would fire this gate with a message telling the
          # author to use "-" and "..." in a screenshot.
          #
          # book/ is scoped to *.html deliberately: mdBook's bundled vendor assets
          # (mark-*.min.js, and its default favicon.svg) contain these byte
          # sequences, so an unscoped scan of book/ could never pass.
          scan() {
            local label="$1"; shift
            local output rc
            output=$("$@" 2>&1)
            rc=$?
            if [ "$rc" -eq 0 ]; then
              printf '%s\n' "$output"
              echo "::error::Found an em dash, en dash, or Unicode ellipsis in $label. Use - and ... (AGENTS.md section 3.5)."
              exit 1
            fi
            if [ "$rc" -ne 1 ]; then
              printf '%s\n' "$output"
              echo "::error::Punctuation scan over $label could not run (grep exit $rc). A broken check is not a passing check."
              exit 1
            fi
            echo "ok: $label"
          }
          scan "sources" grep -rnI -e $'\xe2\x80\x94' -e $'\xe2\x80\x93' -e $'\xe2\x80\xa6' README.md book.toml docs/src theme
          scan "rendered pages" grep -rnI --include='*.html' -e $'\xe2\x80\x94' -e $'\xe2\x80\x93' -e $'\xe2\x80\xa6' book

      # The remap is what makes this worth running: the README's absolute links
      # into the site resolve against the book built from THIS pull request, not
      # against whatever is currently deployed. It is the only check that can
      # catch a README rewrite breaking site navigation.
      #
      # Quoting is load-bearing: double quotes so $(pwd) expands here, and \$1
      # escaped so the capture reference reaches lychee instead of being eaten
      # as a shell positional parameter.
      #
      # --offline blocks network requests, so third-party hosts are skipped and
      # an unrelated site's downtime cannot fail a docs pull request. Remaps are
      # applied before that filter, so our own site URLs are still checked - as
      # local files in the book we just built. An --exclude regex was tried first
      # and could not work: lychee's engine is the Rust regex crate, which has no
      # look-around, so a "everything except our domain" pattern fails to compile.
      #
      # --root-dir resolves the root-relative link in mdBook's generated 404.html.
      - name: Link check
        run: |
          lychee --no-progress --include-fragments --offline \
            --root-dir "$(pwd)/book" \
            --remap "^https://oszkar\.github\.io/balanze([/?#]|$) file://$(pwd)/book\$1" \
            book README.md
```

`--offline` blocks network requests, so third-party hosts are skipped and an unrelated site's downtime cannot block a docs PR. Remaps are applied before that filter, so `https://oszkar.github.io/balanze/...` URLs are rewritten to `file://` paths into the book we just built and are still checked, while repository-relative README links (`docs/PRD.md`, `AGENTS.md`, `LICENSE`) are also still checked as local files.

## The statusline is wired but my Claude Code prompt is blank (Windows)

Almost always the `statusLine.command` path in `~/.claude/settings.json` uses backslashes. Two things mangle it at once: JSON reads `\b` and `\t` as control characters, and Claude Code runs the status line through Git Bash, where a backslash escapes. Both fail silently, so you get an empty line rather than an error.

Use forward slashes, which are valid in Windows file APIs, JSON, and Git Bash simultaneously:

```json
"command": "C:/Users/you/path/to/balanze-cli.exe statusline"
```

If `balanze-cli` is on your `PATH` (which it is after any of the [Install](install.md) routes), the bare form avoids the problem entirely:

```json
"command": "balanze-cli statusline"
```

## Codex and OpenAI segments appear in my statusline even though the app is not running

That is expected, not a bug. When no fresh snapshot exists, `balanze-cli statusline` composes those segments itself: Codex comes from local files, and OpenAI cost is fetched and cached for five minutes - and only when your configured line actually contains `{openai_cost}`, which the default template does not. At most one upstream OpenAI request fires per five minutes across every concurrent prompt.

Starting the desktop app or `balanze-cli watch` produces a fresh snapshot, which takes precedence.

## Balanze is using a lot of CPU while Claude Code is active

It should not: the JSONL reader is incremental and re-reads only what was appended. Sustained high CPU means that has regressed. Please [file an issue](https://github.com/Oszkar/balanze/issues/new) noting roughly how large `~/.claude/projects` is.

## My OpenAI key is rejected

The OpenAI cells need an **Admin** key (`sk-admin-...`), created in your organization's API-key settings. A regular `sk-...` key cannot reach the Admin Costs API and will be refused. `balanze-cli doctor` distinguishes the two.

## Claude data stopped updating

Balanze reads Claude Code's OAuth credential strictly read-only and never refreshes it. When it expires, re-run:

```bash
claude login
```

Balanze picks the refreshed credential up on its next poll. It never writes, mirrors, or backs up that credential.

## macOS keeps asking for Keychain permission

Builds you compile yourself are unsigned, so macOS cannot reliably remember an "Always Allow" grant across rebuilds. The release DMG is signed and notarized and does not have this problem. See [Install](install.md).

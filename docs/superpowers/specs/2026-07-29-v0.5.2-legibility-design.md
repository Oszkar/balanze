# v0.5.2 - Legibility (docs site) - Milestone Spec

Date: 2026-07-29
Status: approved (scope), ready for implementation plan
Phase: 5 (Distribution & Legibility), third sub-milestone

## 1. Context

The v0.5.2 milestone as originally scoped was a single issue - #210, "Docs site: mdBook skeleton + GitHub Pages deploy" - and it is already merged (`2303af5`, PR #233). The site is live at <https://oszkar.github.io/balanze/>, `book.toml` sets `src = docs/`, and `.github/workflows/pages.yml` deploys through the native Actions flow on any push touching `docs/**`.

So the tag could be cut today against a one-bullet changelog. Auditing the live site before doing that turned up three defects that make the milestone worth more than a bookkeeping bump:

1. **The flagship page ships placeholders.** `docs/GUIDE.md` carries nine `📷 [capture: <state>]` lines plus an author-facing blockquote explaining the placeholder convention, all rendered verbatim on the public site. For a milestone themed *Legibility*, that is the headline defect.
2. **An internal design record is published.** `docs/reviews/surface-consistency.html` returns 200 at <https://oszkar.github.io/balanze/reviews/surface-consistency.html>, despite `docs/PRD.md` explicitly classing it as "internal engineering detail, not user-facing."
3. **There are two manuals.** `README.md` lines 57-188 (Install + Using the CLI, roughly 130 of its 241 lines) and `docs/GUIDE.md` (first run, popover, tray, OpenAI, statusline, states, CLI in brief, settings, Linux, troubleshooting) address the same reader with overlapping content. The site inherited that overlap rather than causing it, but shipping a docs site without resolving it means paying the site's maintenance cost while keeping the drift.

v0.5.2 therefore grows from "the site exists" to **"the site is something you would send someone to."** No code changes.

### 1.1 Verified facts this design rests on

Recorded because each one was checked against the live site or the repo, and each drives a decision below.

- **mdBook skips `.md` files absent from `SUMMARY.md`, but copies non-Markdown files verbatim.** `PRD.md`, `ARCHITECTURE.md`, and every file under `docs/superpowers/` return 404 on the live site; `docs/reviews/surface-consistency.html` returns 200. This is why the leak is structural rather than a one-file mistake.
- **All nine named capture states exist** as real entries in `src/lib/gallery/fixtures.ts` (`Settings - configured`, `Cards - two providers`, `Grid - overage billed`, `Grid - two providers`, `Grid - OpenAI connect CTA`, `Grid - cold start (quota loading)`, `Grid - Claude Code not detected`, `Grid - Codex stale window`, `Grid - OpenAI error`).
- **Committed Playwright baselines already cover every state in both themes** (`tests/visual/gallery.spec.ts-snapshots/`, deterministic via a frozen clock and font/image readiness waits) - **but they screenshot `figure.frame`, which contains the gallery's own `<figcaption>` label.** They cannot be copied into the guide as-is without embedding gallery captions in user documentation.
- **mdBook's theme is a localStorage toggle, not `prefers-color-scheme`.** A `<picture>` element keyed on the media query would mismatch any reader who has selected the navy theme on a light OS.
- **`docs/TROUBLESHOOTING.md` is mostly developer-facing** - 8 of its 12 entries concern `cargo check` after a Tauri bump, wiring a new Tauri command, `tauri dev` hanging, the JSONL parser's CPU profile, and similar. Only about 4 address a user of a released build.
- **`docs/SECURITY.md` is a security policy** (supported versions, how to report a vulnerability), which GitHub surfaces in the repository's Security tab.

## 2. Scope

### In scope

1. **Book source boundary** - move book source to `docs/src/`, making "published" a property of location rather than of file extension.
2. **Real screenshots in the user guide** - replace all nine placeholders and drop the author note.
3. **Three new chapters** - Install, CLI Reference, FAQ & Troubleshooting.
4. **README deduplication** - README keeps short-form and links down; the site owns long-form.
5. **Site branding and a link-check gate** - custom CSS keyed to `theme.css` tokens, favicon, sidebar logo, and an offline link check in `pages.yml`.
6. **Housekeeping** - rewrite the PRD's v0.5.2 section to match what shipped, changelog entries, version bump, tag.

### Deferred

- **All code changes.** #214, #204, #198 stay in v0.5.3. #232, #231, #219, #186, #152, #136, #134, #114, #107, #85 stay unscheduled.
- **A changelog chapter on the site.** GitHub Releases owns release history.
- **Versioned documentation** and any search configuration beyond mdBook's default.
- **A dark screenshot set.** See 3.3.
- **Moving `TROUBLESHOOTING.md` or `SECURITY.md` onto the site.** See 3.4.

## 3. Design

### 3.1 Book source boundary

`book.toml` changes `src = "docs"` to `src = "docs/src"`. What moves and what does not:

| Moves to `docs/src/` | Stays in `docs/` |
|---|---|
| `index.md`, `SUMMARY.md`, `GUIDE.md` | `PRD.md`, `ARCHITECTURE.md`, `SECURITY.md`, `TROUBLESHOOTING.md` |
| `assets/` (and the new `assets/guide/`) | `superpowers/`, `reviews/` |
| The three new chapters (3.4) | |

The resulting invariant is one line, and it is the point of the change: **anything under `docs/src/` is public; nothing else is.** Today's rule ("`.md` files are safe unless listed, other extensions always publish") is not something a contributor can be expected to hold in their head, and it fails silently.

Consequential edits:

- `.github/workflows/pages.yml` path filter narrows from `docs/**` to `docs/src/**` (plus `book.toml` and the workflow itself), so editing the PRD no longer triggers a Pages deploy.
- `README.md` asset references (five: the two logo variants, both popover screenshots, the TUI screenshot) repoint to `docs/src/assets/`.
- `docs/GUIDE.md:134` currently links to `TROUBLESHOOTING.md` through a GitHub blob URL; it becomes a relative link to the new FAQ chapter (see 3.4).

`docs/reviews/surface-consistency.html` needs no separate handling once the boundary moves - it stays in `docs/`, outside book source, and stops publishing. It is kept, not deleted: it remains a legitimate internal record.

**Alternative considered and rejected:** relocate the one `.html` file and leave `src = docs/`. Cheaper by a handful of edits, but it fixes today's instance rather than the trap, and the trap is silent.

### 3.2 `SUMMARY.md`

From two entries to five:

```markdown
[Introduction](index.md)

- [Install](install.md)
- [User Guide](GUIDE.md)
- [CLI Reference](cli.md)
- [FAQ & Troubleshooting](faq.md)
```

`index.md` is tightened and stops deferring install to GitHub. It keeps its link to the repository for source and releases.

### 3.3 Guide screenshots

The nine placeholders become real images and the author-facing blockquote at `docs/GUIDE.md:7` is deleted.

**Capture path.** A dedicated Playwright spec (`tests/visual/guide-shots.spec.ts`, run manually like the rest of the visual harness) screenshots the `.pop` element inside each named frame - **not** `figure.frame`, which would embed the gallery's caption - and writes to `docs/src/assets/guide/<slug>.png`. It reuses the existing config's determinism (frozen clock at `2026-01-01T12:00:00Z`, `document.fonts.ready`, image-decode waits). Only the nine states the guide names are captured, light theme only.

This is a second capture path alongside the visual-regression baselines rather than a reuse of them. The duplication is deliberate and small: the baselines exist to detect unintended visual change and are therefore platform-suffixed and caption-inclusive, while the guide assets exist to be read by a person. Wiring one to the other would couple a docs artifact to a test fixture's framing.

**Light theme only.** Because mdBook's theme selector is independent of `prefers-color-scheme`, a `<picture>` element cannot track it, and `default-theme` is already `light`. Shipping one honest set beats shipping two that mismatch half the readers. A dark set is a follow-up if anyone asks.

**Refresh discipline.** These are hand-refreshed when the popover changes, in the same manual-smoke category as the visual baselines themselves (AGENTS.md section 6). The capture spec makes that one command.

### 3.4 Chapters

**Install** (`docs/src/install.md`) - long-form, absorbed from the README: checksum verification commands, architecture caveats (no Intel macOS, no arm64 Windows desktop), the macOS quarantine `xattr` note, Homebrew, and building from source.

**CLI Reference** (`docs/src/cli.md`) - every subcommand with its flags, the exit-code table, the `BALANZE_OPENAI_KEY` and `BALANZE_LOG` environment variables, shell completions, and a pointer to the `--json` schema in `ARCHITECTURE.md`. Hand-written; no generation step, since a clap-derived dump would read worse than prose and would add a build dependency for a five-command tool.

**FAQ & Troubleshooting** (`docs/src/faq.md`) - assembled from the roughly four user-facing entries lifted out of `docs/TROUBLESHOOTING.md` (tray icon absent or doubled, macOS tray clicks, a blank Windows statusline, cross-provider segments appearing without the watcher running) plus the Guide's "States you might see" section, which is FAQ material sitting in a walkthrough.

`docs/TROUBLESHOOTING.md` keeps the remaining developer entries and gains a one-line header declaring itself developer-facing, with a pointer to the site's FAQ for user issues. `docs/SECURITY.md` does not move.

### 3.5 Branding and the link-check gate

**Branding.** `[output.html] additional-css` pointing at a small stylesheet whose accent colors are lifted from `src/theme.css`, plus a favicon and the Balanze mark in the sidebar. A stock mdBook reads as scaffold, which is precisely the bar the PRD's engineering success criteria sets ("reads as intentional, not a scaffold").

**Link check.** A step in `pages.yml`, between build and upload, running `lychee --offline` over the built `book/` directory. Offline mode checks local link targets only; external URLs are excluded deliberately, because a third-party 404 must not be able to block a docs deploy.

The binary is fetched from its GitHub release and verified against a pinned SHA-256, exactly mirroring how that workflow already installs mdBook and for the stated reason: it keeps the step fast and keeps the workspace's vetted Cargo dependency graph untouched. No third-party GitHub Action is added.

This gate is what stops the deduplication in 3.6 from rotting - after that pass, the README and the site link to each other heavily.

### 3.6 README deduplication contract

The README keeps short-form and links down. It never re-explains what the site owns.

| Stays in the README | Moves to the site |
|---|---|
| Pitch, badges, screenshots, the matrix table | Checksum verification commands |
| A compact install table (2 desktop rows, 4 CLI rows) | The macOS quarantine `xattr` note |
| The SmartScreen `<details>` block | `cargo install` from-source detail |
| The roughly ten-line CLI command list | Exit-code table, completions, environment variables |
| Develop, gallery, "Finding your way around", Contributing, License | The `status --json` schema pointer |

The SmartScreen block stays deliberately: it is read at the moment of download, GitHub is the distribution channel, and sending someone to a website mid-download is friction.

Expected result is roughly 150 lines, down from 241.

## 5. Sequencing

Four PRs, in order, with a review checkpoint at each boundary.

**PR 1 - source boundary, branding, link-check.** `src = docs/src/`, the file moves, `pages.yml` path filter and lychee step, `additional-css` plus favicon and logo, README asset repointing.
*Manual tests:* `mdbook build` clean; the site deploys; <https://oszkar.github.io/balanze/reviews/surface-consistency.html> now 404s; `GUIDE.html` and the index still 200; README images still render on GitHub; the lychee step fails as expected when fed a deliberately broken link.

**PR 2 - guide screenshots.** The capture spec, the nine assets, placeholder replacement, author-note removal.
*Manual tests:* `bun run gallery:serve` plus the capture spec produces nine files; no gallery caption is visible in any of them; the rendered guide shows every image in both mdBook themes.

**PR 3 - chapters.** Install, CLI Reference, FAQ; `SUMMARY.md`; the `TROUBLESHOOTING.md` split and its new header; the `GUIDE.md:134` link fix.
*Manual tests:* every chapter renders and is reachable from the sidebar; the CLI reference matches `balanze-cli help` output for each subcommand; link check clean.

**PR 4 - README dedup and release.** The README pass, PRD rewrite, changelog, version bump, tag.
*Manual tests:* every "see the site" link in the README resolves; `cargo check --workspace` after the `Cargo.toml` bump; the em-dash and ellipsis sweep across the full staged diff (AGENTS.md section 3.5).

## 6. Validation

Docs-only through PR 3, so the Rust gates are not implicated until the version bump:

- `mdbook build` succeeds with no warnings, and the lychee offline check passes, on every PR.
- `cargo check --workspace` on PR 4 (workspace `Cargo.toml` touched, AGENTS.md section 6).
- `bun run check` on PR 2 (a new file under `tests/`).
- The em-dash and ellipsis sweep on every commit.
- Post-deploy spot check of the live site at each boundary, since Pages deploys from `main` and the local build cannot prove the published result.

## 7. Risks and open items

- **Screenshot staleness.** Nine hand-refreshed images are nine things that can drift from the UI. Mitigated by keeping the capture to one command and by the state names matching real gallery fixtures, so a removed state fails the capture loudly rather than silently shipping a stale image.
- **Deduplication regressions.** Cutting 90 lines out of the README risks dropping something with no new home. PR 4 is reviewed against the 3.6 table specifically, not just read for flow.
- **Pages deploy is the only real test.** Nothing in per-PR CI renders the published site, so each boundary needs the manual spot check listed in section 5.
- **Chapter drift over time.** The link check catches broken links, not stale prose. Accepted: at one maintainer, the alternative is a doc-testing apparatus that costs more than the drift it prevents.

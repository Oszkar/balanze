# Architecture

Balanze is an actor-model Tauri app. One thread owns canonical state; pollers feed it; the frontend reads it. Currency is `i64` micro-USD; HTTP is concentrated in two clients; secrets route through one keychain wrapper; the JSONL wire format is owned by one crate. The frontend ↔ backend surface is a fixed set of commands and events.

This doc is the architecture reference. Product scope lives in [`PRD.md`](PRD.md); operational discipline (validation gates, change control, test rules) lives in [`../AGENTS.md`](../AGENTS.md).

## Data flow

```
~/.claude/projects/**/*.jsonl ─notify+60s incr.──┐
~/.codex rollout files ────────60s safety poll───┤
OpenAI billing API ─────shared 300s gate─────────┤
Anthropic OAuth (fallback) ───5min poll──────────┤
Claude Code statusLine ───────push (per turn)────┤
Tauri commands ───────────────StateMsg::Query────┤
popover open / refresh_now ───StateMsg::Refresh──┤
                                                  ▼
                              ┌──────────────────────────────┐
                              │   StateCoordinator (actor)   │
                              │   owns: Snapshot, Settings,  │
                              │         AppHandle            │
                              └──────────────────────────────┘
                                          │
                       ┌──────────────────┼──────────────────┐
                       ▼                  ▼                  ▼
                emit("usage_updated") tray.set_icon    emit("degraded_state")
                                      tray.set_title   (Svelte UI)
                (Svelte UI)           (OS tray)
```

The statusLine push is the v0.2 live backbone for Anthropic quota when the user has an active Claude Code session; OAuth polling is the cold-start / no-session fallback (backoff'd, 429-tolerant).

## Boundaries

Strict layering - agents must respect these.

1. **`claude_parser` owns the JSONL wire format.** Other crates consume `UsageEvent` only; field names and line-format quirks do not leak. The incremental/tailing reader (`IncrementalParser`) combines platform file identity (device/inode on Unix, volume/file-index on Windows) with mtime and size to distinguish appends from replacements of any size, decodes only newline-terminated byte prefixes, reports whether a read appends or replaces a file's contribution, skips an unparseable or invalid-UTF-8 *complete* line - a WARN with the skipped count - and advances its byte cursor past the batch, so a partial write or one malformed line cannot stall future appends for that file; the strict batch parser (`parse_str`) still fails fast for callers that want that.
2. **`window`, `claude_cost` are pure functions.** No I/O, no `tokio::spawn`, no logging above `debug`. `claude_cost` is infallible - unknown models route to `skipped_models`.
3. **`anthropic_oauth` + `openai_client` are the only HTTP clients.** Other crates do not issue HTTP requests; the glue crates (`balanze_cli`, `watcher`) may construct a `reqwest::Client` to inject into these two, but all request, reservation, retry, and redaction policy lives here. `openai_client` exposes only its gated Costs operation: a granted reservation performs exactly one request, while every other caller receives cached data or a typed deferred/unavailable result. `anthropic_oauth` retains its caller-selected retry policy and is additionally the only reader of Claude Code's OAuth credential. Both `~/.claude/.credentials.json` / `~/.config/claude/.credentials.json` and the recent macOS login Keychain representation belong to Claude Code and are strictly read-only to Balanze. File credentials are re-read each poll to observe Claude Code's atomic replacements; the Keychain credential is read via `/usr/bin/security` (not `keyring`, so boundary #5 holds) and cached while valid to avoid repeated prompts. A 401 causes one credential re-read and a retry only if Claude Code rotated the bearer during the poll. Expired or still-rejected Keychain credentials enter a 30-minute terminal cooldown before another Keychain read. Balanze never calls the token-refresh endpoint and never writes, mirrors, persists, or backs up credential contents. An expired or rejected credential surfaces `CredentialExpiredReadOnly` (re-run `claude login`). A future explicit file-refresh opt-in is tracked in [#186](https://github.com/Oszkar/balanze/issues/186) and requires a separate settings-schema and secret-boundary change.
4. **`watcher` owns `notify` + the debounce + the 60 s safety poll.** Other crates do not import `notify`. `Watcher::spawn(handle, &Settings, generation) -> Vec<(&'static str, JoinHandle<...>)>` returns one labeled handle per task; default-spawned (3): `jsonl` (notify + 300 ms debounce + a 60 s fallback; reads new bytes only via a per-file byte cursor, owns events per file so truncations, rewrites, and deletions replace or remove that contribution before global deduplication, and neither path full-reparses unchanged files after launch per §3.1), `statusline`, `safety` (a 60 s re-read of statusline + Codex - it no longer scans JSONL, the `jsonl` task's 60 s fallback covers that; its Codex scan gated on `providers.codex_enabled`); conditionally (2): `openai_poll` when `providers.openai_enabled` or a `BALANZE_OPENAI_KEY` env override is set, and `oauth_poll` when `providers.anthropic_enabled`. The caller (`balanze-cli watch`, or the Tauri host) supervises under `tokio::select!`. `WatchedTasks::shutdown` aborts and joins the complete task set, guaranteeing that generation can no longer emit. `Ok(Ok(()))` is graceful (e.g. no OpenAI key) and must not trigger teardown. The CLI treats an `Ok(Err(_))` / panic from any task as fatal and exits with a restart hint. The Tauri host self-heals instead: its supervisor allocates monotonically increasing generations, joins the old generation, applies settings to the coordinator, starts replacement pollers, and then acknowledges the transition. Unexpected task death follows the same generation replacement after emitting a generation-tagged `degraded_state` update and bounded backoff (exponential, 1 s to a 60 s cap). Tasks feed the coordinator directly via generation-tagged `StateCoordinatorHandle::send(StateMsg::Update(...))`.
5. **`keychain` is the only caller of `keyring-core` (plus the OS-native store crates).** All secret reads/writes route through this crate.
6. **`settings` owns `settings.json`.** Every production mutation acquires the persistent sibling `settings.json.lock` with a bounded timeout, reloads the latest file while holding that cross-process lock, applies explicit field-level intent, and atomically publishes via tmp + rename before releasing the lock. The lock file itself is stable and never deleted; locking `settings.json` would be incorrect because atomic rename replaces that file identity. `normalize_on_disk_at` performs its unknown-field-preserving raw-JSON patch under the same lock. Read-only loads remain lock-free because atomic publication exposes a complete old or new document. This is a cooperative Balanze protocol, not a universal filesystem transaction: manual editors and external writers do not take the lock and can still overwrite a committed update. Key set/clear intentionally holds the lock across a possibly prompting macOS keychain operation so cooperating Balanze processes cannot reorder the keychain effect and provider flag; contenders receive the bounded timeout instead. No other crate reads or writes Balanze's settings file directly.
7. **`state_coordinator` is the only writer of the in-memory `Snapshot` and the only driver of tray repaints (via the `Sink` trait).** Pollers send `StateMsg::Update(SourceUpdate { generation, ... })`; the coordinator accepts only the active watcher generation, applies the partial, and notifies the `Sink`. `SettingsChanged { settings, generation, applied }` advances the accepted generation and clears disabled-provider cells only after the supervisor has joined the old pollers; stale updates can therefore never restore a disabled cell. The concrete `TauriSink` (in `src-tauri`) is the only caller of OS tray APIs: it emits `usage_updated` and repaints, deduping by `(ColorBucket, title, tooltip)` (its own `last_painted`) - the tooltip is part of the key because it names the worst window (and now carries both Codex windows), so a same-color/same-title repaint that only changed the tooltip must still paint. A `StateMsg::Refresh` (popover open / `refresh_now`) re-notifies the `Sink` with current state so it can repaint - it never re-fetches, and nothing outside the `Sink` touches OS tray state. The `ClaudeJsonl` partial carries **raw deduped events**, not a finished summary: the coordinator derives the window + API-rate cost via `state_coordinator::summarize_jsonl`, anchoring the rolling window to the latest OAuth `resets_at`. It caches the events, so a subsequent OAuth update (a new reset) re-anchors them - this is what keeps the live `watch` window identical to the one-shot CLI. `SourceUnavailable` carries the same generation and models an intentional not-configured state separately from failure. Both successful and error-slot transitions publish the changed snapshot to durable storage. Only presentation changes invoke `Sink::on_snapshot`; error-only transitions use `Sink::on_snapshot_durable`, which the JSON watch sink publishes but the Tauri sink leaves as a no-op, and emit `degraded_state` without duplicating `usage_updated` or tray work. The actor sends immutable payloads through a bounded-latest `tokio::sync::watch` channel; a dedicated writer performs serialization and atomic fsync on a blocking worker. While storage is slow, pending writes coalesce to the newest snapshot, actor queries and tray updates continue, and coordinator shutdown joins the writer after it flushes or reports the final pending state. CLI watch exits join the pollers and coordinator explicitly so this shutdown contract runs before the runtime is dropped.
8. **`src-tauri` and `balanze_cli` are glue, not logic.** Both turn backend crates into a `Snapshot`, by two routes: the **one-shot** path (`balanze-cli status`) runs `snapshot_composer::compose`; the **live** path (`balanze-cli watch`, or the Tauri host) feeds incremental `StateMsg::Update` partials into the coordinator, which assembles the `Snapshot`. The JSONL → window+cost math is shared across both routes via `state_coordinator::summarize_jsonl` (called by `compose` and by the coordinator merge), so the live path cannot diverge from the one-shot path on the window anchor. Identical inputs ⇒ identical `Snapshot` cells (parity-tested in `integration_4quadrant::compose_parity_against_fixtures`).
9. **Frontend ↔ backend goes through the fixed IPC contract.** Commands: `get_snapshot`, `get_history`, `refresh_now`, `hide_window`, `resize_popover`, `get_launch_at_login`, `set_launch_at_login`, `set_api_key`, `validate_api_key`, `has_api_key`, `clear_api_key`, `get_settings`, `set_settings`, `get_statusline_status`, `set_statusline_wired`, `replace_statusline`, `restore_statusline`. Events: `usage_updated`, `degraded_state`. Adding to this surface needs a design-doc update first.
10. **Currency math uses `i64` micro-USD.** Convert to `f64` only at the display boundary. Every provider's money is converted to i64 micro-USD at its own ingest/parse boundary (Anthropic `extra_usage` cents, OpenAI Admin Costs dollars), so the `Snapshot` holds no `f64` money. `claude_cost` keeps per-token prices in i64 nano-USD with i128 intermediates and saturates at `i64::MAX`.
11. **`codex_local` knows the Codex rollout-JSONL format and is the only reader of `~/.codex/`.** Honors `CODEX_CONFIG_DIR`. Its recursive walker canonicalizes entries, refuses paths outside the canonical sessions root, and tracks visited directories so symlink or junction cycles cannot escape or loop. Other crates consume `CodexQuotaSnapshot`, which carries both rolling rate-limit windows (5h + weekly, classified by duration, never by which JSON slot they land in); a consumer that needs a single "Codex %" figure reduces the two to the worst via `CodexQuotaSnapshot::worst_window`.
12. **`claude_statusline` owns the Claude Code statusLine wire format and the statusLine stanza in Claude's `settings.json`** (read + atomic write, idempotent, no-clobber - mirrors boundary #3). It also owns the shared replace/restore orchestration used by Tauri and the CLI: the displaced command is durably stored through `settings` before Claude's file changes, the Balanze settings lock spans the workflow, reported write failures roll the backup back, and restore retries reconcile an already-restored command. This is a safely ordered two-file protocol, not a cross-file atomicity claim. `claude_statusline` also owns the `<ProjectDirs.data>/statusline.snapshot.json` inter-process bridge: `balanze-cli statusline` writes atomically; `watcher::tasks::statusline` reads on notify. (The reverse-direction `snapshot.json` bridge - host writes the full cross-provider `Snapshot`, `balanze-cli statusline` reads it for the Codex/OpenAI segments - is owned by `state_coordinator`, boundary #7.)

## IPC contract

Frontend ↔ backend, via Tauri commands and events only. Commands return `Result<T, String>` (`anyhow::Error::to_string()`).

| Direction | Name | Purpose |
|---|---|---|
| Command | `get_snapshot` | Current `Snapshot`. |
| Command | `get_history` | Recent rolling-window-sized history. |
| Command | `refresh_now` | Trigger an immediate poll/refresh. |
| Command | `hide_window` | Hide the popover (ESC-to-dismiss); window manipulation stays in Rust. |
| Command | `resize_popover` | Resize the popover window to a content-hugging height (clamped) and re-anchor to the tray/dock. Frontend-driven via `ResizeObserver`; webview holds no window capability. |
| Command | `get_launch_at_login` / `set_launch_at_login` | Read / set the OS launch-at-login state via `tauri-plugin-autostart` (approach A: the OS login item is the source of truth, so there is no `Settings` field to reconcile). Driven from Rust so the webview holds no `autostart` capability; the Windows `Run` key / macOS LaunchAgent I/O runs through `spawn_blocking`. |
| Command | `set_api_key` / `has_api_key` / `clear_api_key` | Store / probe-presence / remove the user-supplied OpenAI key in the keychain (never returns the value). |
| Command | `validate_api_key` | Probe a user-supplied key against the provider WITHOUT storing it (async; one fail-fast month-to-date costs request, the same call the poller makes). Returns `{ ok, retryable, message }` so Settings gives immediate feedback: `ok` authenticated, `retryable` failed transiently (network / 429) so the UI may offer "save anyway", neither means the key is definitively wrong. Never logs or echoes the key. |
| Command | `get_settings` / `set_settings` | Read non-secret config / apply a field-level patch. `set_settings` accepts optional `providers.openai_enabled`, `providers.anthropic_enabled`, `providers.codex_enabled`, and `oauth_poll_interval_secs` fields, applies every present field in one serialized settings transaction, live-applies the exact committed value, and returns that value so the UI cannot retain unrelated stale fields. Backend-owned `seen_welcome` and `statusline` state never cross the write side of this IPC boundary. |
| Command | `get_statusline_status` / `set_statusline_wired` | Read (returns `{ status, command, replaced_command }`) / wire-unwire the Balanze `statusLine` in Claude Code's `settings.json` (no-clobber). |
| Command | `replace_statusline` | Under the Balanze settings lock, replace a foreign `statusLine.command` with Balanze's after durably backing the displaced command up to `settings.statusline.replaced_command`. A reported Claude settings write failure rolls the backup back to its prior value; a rollback failure reports both errors and preserves the safest available backup. Only Claude Code's `settings.json` (the wire) and Balanze's own `settings.json` (the backup) are written - the foreign tool's own config files are never read or modified. The two files cannot be updated atomically, so crash residues are safe and retryable rather than hidden. |
| Command | `restore_statusline` | Under the Balanze settings lock, write `settings.statusline.replaced_command` back as `statusLine.command` (or unwire if the backup is `None`), then clear the backup only after the Claude settings write succeeds. A retry recognizes an already-restored command and clears the stale backup; an unrelated foreign command is never overwritten and keeps the backup. Provider-agnostic. |
| Event | `usage_updated` | New `Snapshot` available. |
| Event | `degraded_state` | A source is stale / errored; surface visually. |

**Status:** implemented: `get_snapshot`, `refresh_now`, `hide_window`, `resize_popover`, `get_launch_at_login`, `set_launch_at_login`, `set_api_key`, `validate_api_key`, `has_api_key`, `clear_api_key`, `get_settings`, `set_settings`, `get_statusline_status`, `set_statusline_wired`, `replace_statusline`, `restore_statusline`, `usage_updated`, `degraded_state`. Commands that perform settings, keychain, subprocess, statusline file, or OS-autostart (Windows `Run` key / macOS LaunchAgent) I/O are async and execute the synchronous operation through `spawn_blocking`; `validate_api_key` is async network I/O. Window-only commands remain synchronous. The key commands never return the user-supplied OpenAI key; set/clear hold the Balanze settings lock across the keychain side effect and provider-flag publication so cooperating processes cannot interleave their ordering. A keychain success followed by settings-publication failure is reported explicitly and remains recoverable by retry, without reading or retaining an old secret for rollback. `set_statusline_wired` delegates to `claude_statusline` and is no-clobber. `replace_statusline` and `restore_statusline` use the lock-scoped, retryable two-file protocol described above; no foreign tool's own config file is ever read or modified. `set_settings` applies a field-level patch, while `set_api_key` / `clear_api_key` apply one provider-field mutation; each passes the exact committed settings value to the single supervised transition described in boundaries #4 and #7. A closed supervisor is returned as an IPC error rather than silently dropping live application. Planned: `get_history` (the durable local history it reads is deferred - revisited post-1.0 with the dashboard; the v0.4.x CLI `export` re-derives the series from JSONL on each run and persists nothing, so `get_history` stays planned, tied to whenever storage lands). `refresh_now` today re-emits the current snapshot to the sink (repaint + catch-up); an on-demand provider re-poll is a later follow-up.

The CLI `--json` schema is the same `Snapshot` rendered through a presentation DTO (`crates/balanze_cli/src/json_output.rs`): the document carries a top-level `schema_version` (currently `1`) so a consumer can detect a breaking change, and every money cell is `{ value_micro_usd: i64, source, confidence, details }` - OpenAI Admin Costs included, converted to i64 micro-USD at the `openai_client` parse boundary so no money cell is `f64` - so consumers tell `jsonl_list_price` / `estimate` apart from `openai_admin_costs` / `real` and `extra_usage_billed` / `real` from the wire shape. Two extra cells (v0.2): `claude_statusline` carries the live `StatuslineFilePayload` envelope (Claude Code's session estimate - a distinct cost tier, no money normalization); its `rate_limits` block carries `five_hour`/`seven_day` (unchanged position) plus a `windows` array with every rate-limit window the statusLine payload reported, mirroring `claude_oauth.cadences` - a statusLine-sourced snapshot is never capped at the two named windows. `.pace` carries a per-window array (`key`, `used_fraction`, `elapsed_fraction`, `ratio`) derived from the OAuth cadence bars - used % vs elapsed % of each quota window (5h, 7d) plus their ratio, computed by `window::pace`; `ratio` is null right after a window reset. `watch --json` reuses this DTO, one JSON document per line. Identifiers (`org_uuid`, Codex `session_id`) are redacted unless `-v`.

**On-disk IPC files.** Two atomic JSON files bridge processes (distinct from the Tauri command/event surface above), flowing in opposite directions:

| File (`<ProjectDirs.data>/`) | Writer | Reader | Payload |
|---|---|---|---|
| `statusline.snapshot.json` | `balanze-cli statusline` (every turn) | `watcher::tasks::statusline` (on notify) | `StatuslineFilePayload` (`schema_version` 2) - Claude session estimate + a generic rate-limit window list (`RateLimits.windows`, not just five_hour/seven_day; boundary #12) |
| `snapshot.json` | `state_coordinator`'s coalescing snapshot-writer task, from whichever host owns the coordinator (the Tauri app or `balanze-cli watch`) | `balanze-cli statusline`, when fresh (within 120 s of `captured_at`) | `SnapshotFilePayload { schema_version, captured_at, snapshot }` - the full cross-provider `Snapshot`; fills the Codex quota + OpenAI billed-$ statusline segments (boundary #7) |

The statusline does no network on the `snapshot.json` read path; Claude segments always come from stdin (the no-arg `balanze-cli statusline` contract is frozen - Claude Code invokes it once per turn, piping the session payload). An additive `statusline restore` subcommand exists (restores the backed-up foreign statusLine or unwires; it does not read stdin; the no-arg + stdin contract is unchanged). An absent or unreadable file degrades to a Claude-only line. Both files use the same atomic tmp+fsync+rename discipline and a `schema_version` probe; neither holds secrets.

**OpenAI Costs gate.** Every OpenAI Costs consumer routes through `openai_client`: one-shot `status`, `export`, the live watcher, setup/doctor/Tauri key validation, and statusline self-compose. Its request identity combines the exact key, normalized API base URL, and operation tag, but only a fingerprint is persisted. OpenAI organization selection is not supported, so the key's organization is the request scope. The schema-versioned store at `<ProjectDirs.cache>/statusline/openai-cost.json` (or `<BALANZE_CACHE_DIR_OVERRIDE>/statusline/openai-cost.json`) holds at most 8 identities and migrates the prior single-entry statusline cache. A stored success has one source of truth: either full `OpenAiCosts`, whose headline is derived from its total, or a legacy-migrated headline without line items.

A contender takes one store-wide `create_new` lease only for read-migrate-write transactions. The owner rechecks under that lease, publishes `InFlight { started_at, token }` atomically, and releases the lease before network I/O. Publication grants exactly one HTTP attempt and reserves that identity for the half-open interval from `started_at` through 300 elapsed seconds on every outcome, including cancellation, crash, and completion-publication failure. There is no in-call retry. Completion is token-checked, so a late attempt cannot overwrite a successor. Live lease candidates expire after 10 seconds; callers without usable data wait at most 250 ms for a transaction to finish. Gate, storage, schema, or lease failure fails closed and performs zero HTTP.

Within the reservation, a current-month full success satisfies full-data callers. Failure, an in-flight attempt, a legacy headline, or a prior-month success returns a typed deferred result, optionally carrying a cached headline. This is deliberately literal across UTC month rollover: an attempt started just before the first day of a month can defer `status`, `export`, watcher updates, and key validation for up to 5 minutes into the new month. Statusline alone may render the prior-month headline with its stale marker. Once 300 seconds have elapsed, the next caller can reserve and fetch the current month.

When no fresh `snapshot.json` exists, `balanze-cli statusline` still self-composes Codex from local files. It asks the OpenAI gate only when a configured line contains `{openai_cost}`; the default template therefore performs no key resolution, gate/cache I/O, lease acquisition, or OpenAI HTTP. A fresh `snapshot.json` wins whole. Otherwise self-composed cells are merged over stale snapshot cells per source, so a last-known value remains visible with its staleness marker. The self-compose path never reaches `anthropic_oauth`.

## Errors and degraded state

- App-level results use `anyhow::Result<T>`. No `.unwrap()` outside tests.
- A library crate exposes its own `thiserror` enum where a consumer pattern-matches the variants or needs typed classification (AGENTS.md §2.1): `claude_parser` (`FileMissing`, `IoError`, `SchemaDrift { line, message }`), the IPC-file readers `claude_statusline::FileIoError` / `state_coordinator::SnapshotFileError`, `settings`, `keychain`, `codex_local`, `watcher`, and the provider clients. Keep each variant surface minimal and path/content-safe.
- There is no `DegradedState` type. Degraded state is carried by the `Snapshot`'s per-source `*_error: Option<String>` slots plus the `degraded_state` IPC event; the coordinator's boundary is string-erased (see boundary #7). A typed error category on the Snapshot - so `status` and `doctor` share real types rather than substring sniffing - is a known open item (`balanze_cli::exit::looks_like_auth`) and needs a Snapshot schema change.
- Long-running tasks (file watcher, polling, the coordinator itself) are supervised with a retained `JoinHandle` + `tokio::select!`. A coordinator exit/panic is fatal on both hosts (the CLI returns; the Tauri host calls `AppHandle::exit` on a genuine panic, but not on a shutdown abort). A watcher-task `Ok(Err)` / panic is fatal in the CLI (`watch` exits with a restart hint); the Tauri host surfaces a `degraded_state` for the affected source and re-spawns the set with bounded backoff (self-heal, not silent freeze).
- External I/O retries via `backoff` (`standard` = 30 s × 2ⁿ cap 10 min; `fail_fast` = 0). Idempotent GETs retry on 429 + 5xx + transport. Balanze never calls Anthropic's token-refresh endpoint.
- IPC errors surface to the UI as a `degraded_state` event; the tray icon shows a warning dot.
- "Unavailable / not configured" is a **neutral** state, distinct from degraded: a source whose prerequisite is absent (Claude Code not installed, so no OAuth credential) reports `StateMsg::SourceUnavailable`, which sets `Snapshot::claude_oauth_unavailable` and repaints without an error - the tray shows the neutral bucket (not the warning dot) and the cell reads "not configured" rather than spinning on a loading state. Only `ClaudeOAuth` carries this marker today.
